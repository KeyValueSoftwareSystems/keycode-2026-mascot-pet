# Decisions

Every deviation from `docs/PROMPT.md`, from the GitHub issue, or from openpets — one line each, with
the reason. The brief asks for this log because a brief written against fetched docs and a
read-not-run reference repo is wrong somewhere, and the record of where is part of the deliverable.

Grouped by whether the brief was **wrong**, **silent**, or simply **improved on**.

---

## The brief was wrong

| # | Decision | Why |
|---|---|---|
| 1 | **`steps(n, jump-none)` with `to` one frame short**, not `steps(n)` with `to: -n×frameWidth` | Measured: with the naive form, a finite animation's after-phase value is column *n* — which `freeCells` confirms is transparent for `waving` and `jumping`. Patching the generated CSS to that form produced a capture with **0 opaque pixels**: the pet vanishes. The shipped form holds the final frame at 47.1% fill. |
| 2 | **Floor formula corrected** to `windowY = floorY - (spriteOrigin.y + frameHeight - footInset)` | §4.3's version added the bubble height, double-counting: the bubble sits *above* the sprite, so adding it lifted the pet by the full 112px bubble area. |
| 3 | **Window height ends at the sprite's lowest opaque row**, not the cell bottom | Sized to the full 208px cell, the bottom 16 rows are transparent, so feet-on-floor needs the window to hang below the work area — which macOS clamps, silently lifting the pet by exactly `footInset`. Caught by assertion A4. |
| 4 | **Reminder miss comparison is `>=`, not `>`** | The brief says "past by more than 2× its interval". A three-hour sleep leaves the 60-minute reminder overdue by *exactly* 2×, so `>` fires it — precisely the wake-up backlog the rule exists to prevent. |
| 5 | **Per-frame and union mask fill are different numbers** | §5.4's "~20% fill still holds" is per-frame (measured 20.9%); the union the mask covers is 35.3%, and the 4px cell grid 37.7%. A test asserting the wrong one is simply wrong. |
| 6 | **Anti-proof greps fixed** | Unanchored `lease` matches "please", `lan-` matches "plan-", and the CSS grep matched the *generated* stylesheet beside the hand-written one. Now word-anchored, `--exclude`d, and enforced as tests rather than commands to remember. |
| 7 | **M7's exclusion list omitted `pet/spritesheet.png`** and the emoji font | The renderer bundle already contains both; shipping the originals paid for them twice. The font duplicate alone was 9.75MB of a 13MB archive. |
| 8 | **openpets' overflow eviction is a bug** — evict the `(rank, seq)` minimum, not `queue.shift()` | Their queue is sorted rank-descending, so `shift()` drops the *highest*-priority pending entry: the opposite of the brief's "drops oldest `low` first" and of any caller's expectation. |
| 9 | **openpets' coalescing key is arbitrary** — compare against the newest entry by `seq`, not the queue tail | In a rank-sorted queue the tail is whatever sorts last. "Back-to-back" means most recently enqueued. |
| 10 | **Linux is XWayland, not native Wayland** | openpets forces `--ozone-platform=x11` unconditionally, because native Wayland forbids a client positioning its own toplevel — which breaks motion, drag and z-order together. The brief treated native draggable regions as the primary Linux path; they are an opt-in fallback behind `KEYCODE_PET_OZONE=native`. |
| 11 | **Windows needs `disable-features=CalculateNativeWinOcclusion`** | Absent from the brief entirely. Without it Chromium's occlusion tracker stops painting every window on a display while a fullscreen app is active — a transparent pet goes blank with its z-order intact. Directly fatal to P1. |
| 12 | **Always-on-top needs a 1s re-assert on Windows**, not just the cache-bust toggle | The shell's demotion sweep re-strips `HWND_TOPMOST` every ~2–4s during fullscreen, so a slower cadence loses the race. |
| 13 | **Emoji font is 4.8MB, not ~1.6MB** | The COLRv1 build is still about half the CBDT build openpets ships, but the plan's estimate was 3× optimistic. The CSP also needs `font-src`, which the brief does not mention. |

## The brief was silent

| # | Decision | Why |
|---|---|---|
| 14 | **Redirects followed manually, max 3 hops, scheme re-validated at each** | With `redirect: 'follow'` the HTTPS-only rule constrains only the initial URL, so `302 https → http` is taken silently and the rule is void. openpets uses `node:https`, which does not follow redirects at all, so the case is simply absent there. |
| 15 | **Strict envelope, per-entry parsing** for the manifest | The brief says `.strict()` but never says whether one malformed entry kills the batch. With a naive strict array it does — one typo'd field silences every announcement for every install. |
| 16 | **Change detection is a body hash, not `304`** | With `cache: 'no-store'` and a hand-set `If-None-Match` there is no cache entry to revalidate; how a given stack surfaces a bare 304 is not worth depending on. The ETag stays as bandwidth politeness. |
| 17 | **Manifest timestamps require an explicit UTC offset** | `2026-08-01T09:00:00` means different instants in different timezones, and a broadcast window that shifts by the reader's location is not a schedule. |
| 18 | **Bidi overrides and isolates stripped from bubble text** | `textContent` closes script injection but not spoofing: those characters are inert and reorder everything after them, so the *visible* text can differ from the manifest. U+200D and U+FE0F are deliberately kept — stripping them breaks emoji. |
| 19 | **Backwards-clock rule for reminders** | A deadline further out than one interval means the clock jumped back (NTP step, timezone edit). Without this the reminder parks for however far it moved. |
| 20 | **`changed` gates the reminder settings write** | The tick runs 5,760×/day; an unconditional dirty flag turns the 500ms debounce into a disk write every 15 seconds, forever. |
| 21 | **`seenBroadcastIds` written with a forced flush** | "Shown exactly once, ever" is a durability claim; the debounce leaves a window where a crash re-shows the message. |
| 22 | **A file logger** | A packaged macOS app has no usable stdio. The first packaging failure was completely opaque until this existed. About shows the log path so a bug report can include it. |
| 23 | **A crispness assertion (A6)** | "Pixel art renders crisp" is acceptance criterion 5 and otherwise only checkable by eye. At 2× every source pixel must be a uniform block: 100% with `pixelated`, 12.5% without — verified by deliberately breaking it. |

## Improvements and choices

| # | Decision | Why |
|---|---|---|
| 24 | **`asar: false`** | Electron 42 silently fails to load an ESM entry point from inside an asar: the process starts and never runs its main script, with no error anywhere. asar was never a security boundary, so the cost is tidiness and the gain is an app that runs. |
| 25 | **Per-state `@keyframes` duplicated per nonce**, rejecting openpets' single-keyframes-plus-custom-properties design | A CSS animation restarts only when `animation-name` changes. With one shared animation, local time grows for the whole session, so a finite state selected later is already finished and paints one static frame. The nonce is what makes re-triggering the *same* state replay, and keeping it in main keeps restart policy where behaviour belongs. |
| 26 | **Animation completion is state, not a `setTimeout`** | openpets uses `setTimeout(durationMs × iterations)`, which drifts, leaks on state change, and cannot be exercised headlessly. `animationEndsAt` is observed by the existing tick. |
| 27 | **Direction pushed from main**, never diffed from window `move` events | openpets diffs `getPosition()` with a 180ms debounce, which fails silently to a permanently idle sprite if a compositor swallows position writes. |
| 28 | **Alpha-mask hit-testing** — original work, not a port | openpets uses a padded DOM rect. The character fills ~21% of its cell and the margin is mostly horizontal, so a bounds test eats clicks across a wide invisible band. The mask is a union across all frames, never per-frame: per-frame would make the grabbable area pulse with the animation. |
| 29 | **`window.setShape()` for Linux click-through** | Electron cannot forward hover on Linux, so a click-through window there is permanently ungrabbable. Best effort: X11-only, re-applied after navigation, degrading to a fully interactive window. |
| 30 | **Sprite generators landed in M2, not M3** | So the transparency gate could screenshot the real sprite rather than a placeholder — and `setShape` and hit-testing need the mask regardless. M3 became purely the seam-driven motion engine. |
| 31 | **`x` is a float in `MotionState`** | Sub-pixel accumulation becomes inherent and rounding happens once at the `setPosition` boundary, replacing openpets' explicit `fracX`/`fracY` bookkeeping with less code. |
| 32 | **Jump probability is per second, not per tick** | Otherwise changing `tickMs` silently changes the pet's personality. |
| 33 | **Drag follows `getCursorScreenPoint()`**, not renderer coordinates | Renderer `screenX/screenY` dies exactly when mouse forwarding dies, and forwarding dying mid-drag is a documented failure mode on macOS and Windows. |
| 34 | **A real `toast.html` with its own preload**, not openpets' `data:text/html` URL | A data: URL has an opaque origin and cannot load the bundled font, and a template-string page puts HTML-string interpolation of untrusted text in the codebase. There is now no interpolation anywhere. |
| 35 | **Toast layout recomputed from the current list** | openpets' slot counter is never compacted, so destroying a middle toast leaves a visible hole. |
| 36 | **The arbiter is pure; the host owns the only timer** | openpets' arbiter owns `setTimeout` handles, which makes it impossible to reason about at an instant or test as a unit. |
| 37 | **`aliases` block in `spritesheet.json`** for undrawn states | The reaction map keeps naming the state it *wants* (`stretch`), so when the art lands the only change is deleting one alias entry. The generator validates that every alias target exists, which is what caught `stretch-reminder` pointing at nothing. |
| 38 | **Electron pinned `^42`** though 43.2.0 is current | Every platform workaround ported from openpets was validated against 42. |
| 39 | **No `electron-updater`** | Squirrel.Mac needs a consistent valid signature across versions; with `identity: '-'` the check fails and the update silently does not apply. The one platform verifiable here is the one where auto-update is structurally impossible. Runtime dependencies stay at exactly `zod`. |
| 40 | **`checkNow` always reports an outcome** — a carve-out from "failure is silent" | Background silence is right; silence after a person clicked a menu item and is waiting reads as a broken menu. Reported by toast, not dialog: a modal breaks the illusion and with the dock hidden can open behind everything. |
| 41 | **`zod` and `main` declared at the workspace root** | electron-builder reads the app entry and runtime dependencies from the root `package.json` in this layout, even though `apps/desktop` is where they belong semantically. |
| 42 | **Icons and the tray glyph are derived from the art** | Keeps locked decision #10 whole: a Keycode-branded pack regenerates its own icons. The tray glyph is a coverage-downsampled alpha silhouette because a full-colour sprite at 16px is mud. |
| 43 | **`position` keyed by display *geometry*** | Display ids are not stable across reboots, so an id-keyed position silently resolves to "no saved position". *(The second half of this decision — "storing only `x`" — was reversed in v1.2.0; see #51.)* |
| 44 | **The bubble is a speech bubble anchored to the character**, not a panel anchored to the window | The brief and the first implementation pinned it across the window's top edge, which puts it ~84px clear of the head: the window is 360px wide for a 107px body and the cell has transparent padding above the hair. It read as an unrelated notification that happened to be nearby. Now it hugs its text, centres on the body, and has an outlined tail pointing at the head. |
| 45 | **`--body-top` is the per-state head top, not the union bbox top** | The union is the minimum over every pose, and on this art `review` reaches 23px above idle's hair — so a union anchor floats that gap in the pose the pet is in most of the time. Generated per state (`headTopByState`) so no offset is hand-typed; per state and not per frame, because a per-frame anchor makes the bubble bob with the animation. |
| 46 | **White fill with a dark outline, opaque** | It is what a speech bubble looks like, and the panel it replaced was translucent — over a busy window that makes 13px of text people are meant to act on hard to read. Tone moved to a coloured left edge so the shape reads as speech first. The corner toast stays dark: it is a notification surface, not the pet speaking. |
| 47 | **A2 excludes the bubble via a reported `bubbleFloorY`, gated on main saying a bubble is actually visible** | Once the bubble sat above the hair it painted inside the transparency ring — above *and* to both sides, since it is wider than the body. The choice was to loosen the threshold, skip the assertion, or bound it exactly; main reports the current pose's head top, below which no bubble pixel can exist. Gated on the frame carrying a bubble rather than on the harness's own `--callout` flag, because a broadcast or a reminder raises one with no flag involved — that version would have failed the regenerated M6 and M8 evidence runs. |
| 48 | **The sprite rect is sampled at capture time, not at `window-ready`** | It was read from the startup event, so once the pet walked the assertions indexed the region it had left. That fails on a correct build when you are lucky and checks the wrong pixels when you are not — it produced two spurious A1/A3 failures before being found. |
| 49 | *(Superseded by #76 when the repo went public.)* **The broadcast host is a static file on an existing nginx box, not a new service** | The client was built to need exactly two things of a host: HTTPS and an ETag. Plain nginx gives both for free, plus `Content-Type: application/json`, so there is no application to deploy, no auth to administer and no second server to keep alive — publishing is `scp`. It also means the packaged build's broadcast path works for the first time, since the default is no longer a loopback URL a shipped build must refuse. The cost is that the manifest is world-readable, which the client already assumed and `docs/BROADCAST.md` already warned about. |
| 50 | *(Superseded by #77; the validation survived, the transport did not.)* **`manifest:publish` validates with the client's own parser and refuses to upload if it fails** | Per-entry parsing means one bad notification costs only itself, but a bad *envelope* means every client ignores the whole file. That single mistake silences every announcement for everyone and is invisible until someone notices nothing has arrived for a week, so it is worth a non-zero exit on one machine instead. Writing it caught two field-name errors in the reporting code (`startsAtMs`, and `dropped` being objects) on its first dry run. |
| 51 | **`position.feetY` is now stored, reversing half of #43** | #43 argued a persisted `y` could only ever be a stale value fighting a fresh derivation. That was right for as long as the floor was the only place the pet could be. Once it can be dragged anywhere, a height is the user's *intent*, which is not the same kind of thing as a cached derivation — so a freely placed pet stores its height and a floor-locked one still stores nothing and is still re-derived. |
| 52 | **`floorLocked` is a flag, not `feetY === floor.y`** | The two states differ in behaviour, not just value: locked means y is *re-derived* every tick (so a Dock resize moves the pet), free means it is only *clamped*. Inferring the flag from equality would make a pet that happens to be dropped exactly on the floor behave differently from one dropped a pixel above it, and would silently convert a user's free placement back to floor-locked whenever a resolution change pushed it down. |
| 53 | **Settings migrate forward rather than resetting** | The schema is a `strictObject`, so *adding* a field makes every file from an older build fail validation, count as corrupt, and get replaced by defaults — silently wiping someone's toggles and their pet's position because a new field appeared. A chained per-version migration was needed the moment the schema stopped being frozen. A version from the *future* is still treated as corrupt: guessing at a shape a later build wrote would corrupt it further. |
| 54 | **`DisplayManager.floorFor` deleted** | It was a second, never-called definition of the placement envelope. Teaching only one of two duplicate definitions about the new vertical bounds is how they start to disagree, so the unused one went. |
| 55 | **A `place` harness command** | The harness has no cursor, so a real drag cannot be synthesised — but free placement is a visual claim and "trust me, it moves" is not evidence. `place` drives the same path a drop ends at, which makes the placement and clamping assertable from a screenshot; the pointer plumbing itself stays a manual check. |
| 56 | **Pet size is a CSS `transform`, not a resize** | The generated keyframes step `background-position` in absolute pixels off the unscaled sheet, so changing the element's width/height or its `background-size` would invalidate every one of them. A transform from `top left` leaves that arithmetic untouched, and `image-rendering: pixelated` still applies through it. |
| 57 | **The mask is never rescaled; the scale is applied at the two screen boundaries** | Three masks for three sizes is three things that can disagree. Instead a hit-test divides by the scale on the way in and a screen rect multiplies by it on the way out. Hit padding is divided too, so the grab margin stays the same size *on screen* at every pet size — otherwise a small pet is proportionally as easy to grab but absolutely much harder. |
| 58 | **`large` stays 1.0, and `medium` is deliberately soft** | Pixel art is only exact at whole-device-pixel scales, and 0.75 × 2 = 1.5. Choosing 1.5/1.0/0.5 would have made all three exact but renames today's size to "medium" and makes "large" bigger than anything shipped. Keeping the shipped size as `large` was the explicit choice, so `medium` resamples and A6 skips it rather than pretending otherwise. |
| 59 | **The window width does not scale with the pet** | Bubble text stays 13px at every size, because a bubble at half size is unreadable and being read is its entire job. Only the window's height follows the sprite. |
| 60 | **`pet.placement` is a getter** | It was a plain property, so `setScale` reassigning the local left every consumer — the frame, the sprite rect, the floor envelope — reading the construction-time scale forever. The renderer painted a resized pet while main still described the old one; A1 caught it as "only 10.8% of the sprite rect has alpha". A value-copied snapshot of mutable state is invisible until something mutates. |
| 61 | **A6's block size is the display scale × the pet scale** | It assumed 2, which was right while `large` was the only size. Left alone, `small` (1 device pixel per source pixel — pixel-exact by construction) reported 18% uniform and read as a smoothing regression. The assertion now runs only when the ratio is a whole number >= 2 and says why it skipped otherwise. |
| 62 | **Reminder intervals are one radio group per reminder, Off included** | "Enabled" and "how often" are one decision from the user's side, and an Electron checkbox cannot carry a submenu — so the alternative was two menu entries per reminder. Turning a reminder off keeps the chosen interval, so switching it back on restores what the user picked rather than reverting to the default. |
| 63 | **Setting an interval clears the pending deadline** | Otherwise the new interval inherits a deadline computed from the old one: picking "every 5 min" on a 45-minute reminder still waits up to 45. The scheduler's rule 2 then reschedules from now, and the action evaluates immediately rather than waiting for the next 15s tick. |
| 64 | **A chosen interval is `null` until chosen** | Not laziness — it is the only representation that lets a team default apply without ever overriding a local choice. Storing the built-in 45 eagerly would make every install look like it had opted in, and a default could then never reach anybody. |
| 65 | **Manifest defaults, never overrides — and no `enabled` field** | Defaults may suggest *how often*, never *whether*. An `enabled` field would let remote text switch a reminder back on after someone turned it off, which is remote control of a machine rather than a shared default. The schema rejects it, and a test asserts the block has exactly the two interval keys. |
| 66 | **Manifest defaults are never written to disk** | Nothing remote outlives the process that received it, so there is no stale remote policy to reason about after a restart and a hostile default cannot persist. The cost is the second between launch and the first poll, which is nothing against a 45-minute reminder. |
| 67 | **`petSize` is not a team default** | Cosmetic personal preference, so a team default has no reason to exist — and supporting one would mean adding a "never chosen" state to `petSize` purely to enable it. Offered and consciously dropped rather than silently omitted. |
| 68 | **`manifest:publish` refuses to publish `defaults` without `--allow-defaults`** | The envelope is strict, so a `defaults` key makes every pre-v1.4.0 client reject the *whole file* — not the block, the entire manifest, silently. That is a fleet-wide broadcast outage caused by adding a field, and it is the one deployment order that cannot be undone by editing the file back. |
| 69 | **`reminders` is spread before patching deadlines** | The 15s tick writes the two deadlines; without the spread it would erase the chosen intervals every 15 seconds. Caught by the type system the moment the field was added, which is the argument for the whole object being one strict schema. |
| 70 | **`defaults` is a loose object, while the envelope stays strict** | Strictness is right for the envelope — a typo'd top-level key should be loud, not a setting that mysteriously does nothing. Inside a block designed to grow it inverts: every new default would make every already-installed client reject the *whole manifest* and go silent. An ignored unknown key costs one default; a rejected envelope costs every announcement for everyone. It also strengthens the trust boundary — a `waterEnabled` field cannot force a reminder on because it does nothing at all, rather than merely being rejected. |
| 71 | **`pollMinutes` comes from the manifest, with the env var still winning** | The broadcast cadence is a publishing decision, not a shipping one. The env override keeps precedence because it is the knob used to *debug* the manifest, and a remote value that could override it would be able to hide itself. Receiving a new value recomputes the pending wait immediately, or shortening the interval would first require the old longer wait to elapse. |
| 72 | **A broadcast with no `durationMs` never expires** | An announcement sent to everybody is worth acknowledging, and a six-second bubble is one you can miss by looking away. Absence means "wait to be clicked" rather than "use the default"; setting a duration is the opt-out. Safe to publish to older clients, which simply show it briefly. |
| 73 | **The dismissible bubble shows a ×** | A notification that never leaves and gives no hint that clicking clears it reads as stuck, not as waiting. The mark is signage with `pointer-events: none` — the whole bubble is the hit target. |
| 74 | **The renderer reports the bubble click; main decides what it means** | It used to gate the report on `data-clickable`, which is a behavioural decision living in the view. Now main opens the link if there is one and dismisses either way. Same seam rule as everything else: the view reports, main owns policy. |
| 75 | **The smoke harness runs in its own `--user-data-dir`** | The single-instance lock lives in `userData`, so a packaged pet running on the same machine made every run exit instantly — and silently, because the `unref`'d wait timeout left nothing to keep node alive, so a run that did nothing printed the banner and exited 0. It also stops leftover manual state shaping evidence: one screenshot came out `small` from a menu click hours earlier, and a broadcast test consumed the id it was demonstrating. |
| 76 | **The manifest moved to GitHub Pages, and the nginx publisher was deleted** | Going public made a second, hand-operated transport pure liability: two ways to publish means one of them is stale, and the SSH path put a personal host alias in a public repo for no gain. Pages advertises `max-age=600`, and the poll interval was set to 10 on the assumption that a shorter one could not beat the cache. **Measured afterwards, that was wrong** — Pages purges its CDN on deploy (`x-cache: MISS`, `age: 0`, new content served with no cache-buster), so the max-age only governs an *unchanged* file. The interval is 1; see #81. What it buys is that **publishing is a commit**: remote text that appears above everything on a colleague's screen now goes through the same review path as code. |
| 77 | **`pnpm notify` generates the id and requires an expiry** | Both were repeatedly got wrong by hand. Ids are permanent dedupe keys, so reusing one silently shows nothing to anyone who saw it before — the worst failure shape, because the publisher sees a successful push. And every message phrased relative to now ("starting in 15 mins", "in 30 days") was published with a week-long window and would have been wrong for whoever installed later. |
| 78 | **The per-poll cap defers rather than discards — and needed the unchanged short-circuit disabling** | Capping at 3 was meant to stop a fresh install getting ten stacked sticky bubbles. But change detection is on the body hash, and a manifest nobody has edited hashes the same forever, so the held entries were never reconsidered: the cap *dropped* them. Caught by the test asserting all eight of eight eventually arrive — it saw three. The poller now skips the unchanged short-circuit while anything is held, and re-parses the last body after a 304. |
| 79 | **"Report a problem…" instead of a crash-reporting SDK** | Sentry would mean a new runtime dependency (a test asserts the list is exactly `zod`), a CSP change, and reversing the documented "no telemetry" property. The menu item copies a filled-in report and reveals the log for the user to attach. The cost is honest: only self-reported problems, and no native crash data. Revisit when the volume justifies the reversal. |
| 80 | **The app keeps the name "Keycode Pet" despite the repo being `keycode-2026-mascot-pet`** | A repo slug is not a product name, and `app.setName()` feeds `userData` — renaming would move the settings directory and silently reset every existing install's position, size, reminder deadlines and seen-message list. A rename is possible, but it needs a migration, not a string edit. |
| 81 | **Poll interval is 1 minute, in the manifest and as the built-in** | The 10 in #76 came from assuming Pages' `max-age=600` would serve stale content for ten minutes, making a shorter poll pure waste. Measuring it showed a purge-on-deploy instead, so a 1-minute poll delivers in about a minute. The bandwidth argument does not bite either: the manifest is ~500 bytes and most polls answer 304, so a client costs well under a megabyte a day. |
| 82 | **Four screenshots purged from history, not just from HEAD** | They were full-display `screencapture` composites that included a working desktop: workspace names, internal ticket titles, a terminal mid-session. Deleting from HEAD alone leaves them fetchable in a public repository forever, and the window to rewrite was open only because the repo had 0 forks and 0 clones — that is not a property that survives waiting. The `*.window.png` captures were never at risk: `capturePage()` renders the pet window's own pixels and nothing else, which is now the documented rule for any new evidence. |
| 83 | **MIT, replacing `"license": "UNLICENSED"`** | The repo was made public while its metadata said proprietary, which meant nobody could legally use or contribute to something described as open source. MIT matches openpets, already credited in THIRD-PARTY-NOTICES.md. |
| 84 | **Publishing a notification is a `workflow_dispatch`, not a script people must clone for** | The primary path is now Actions → Notify: type the message in a browser, no checkout, no Node, no shell. It calls the same `scripts/notify.mjs` rather than reimplementing the rules, and inputs reach it through the environment rather than the command line — a message containing a quote would otherwise be shell syntax, and the entire point is that non-developers type into it. |
| 85 | **`--duration` accepts seconds, and refuses out-of-range values** | It only parsed `m|h|d`, while the client clamps a bubble's display time to 2000–30000ms — so the smallest expressible value already exceeded the maximum and the flag could not name a single legal duration. It now takes `2s`–`30s` and rejects anything else rather than letting the client silently clamp 5 minutes down to 30 seconds. |
| 86 | **`SHA256SUMS-*.txt` published with every release** | For a signed app this would be ceremony. For an unsigned one it is the only integrity check a user has: there is no signature for the OS to check, so a published digest is the difference between trusting a download and verifying it. |

## Deliberately not done

| Item | Status |
|---|---|
| ~~A real broadcast host~~ | **Done.** A static file on an existing nginx box, `https://demos.doylefermi.freeddns.org/keycode/manifest.json`. A client that needs only HTTPS and an ETag needs no application and no auth to administer, so this is `scp` rather than a service — see decision #49. |

| Windows and Linux verification | Not possible from this machine. See `docs/VERIFICATION.md`. |
| Developer ID signing and notarization | Not done — no certificate. This is what makes macOS refuse to open the app from an Applications folder, and it is the whole content of the `/Applications` failure originally logged as unexplained. Isolated to Gatekeeper by running a byte-identical `ditto` copy from three paths: build output runs, a scratch directory runs, an Applications folder is blocked. A human approves it once, or a certificate removes the step. |
| `stretch` animation art | Aliased to `jumping`. The trigger path is complete and testable. |
| `drink` animation art | Row 6 reclaimed; plays the idle frames until drawn. The reminder path is complete. |
| Keycode-branded art | Ships on the `pixel-coder` placeholder. `docs/ASSETS.md` documents the zero-code-change swap. |
| Shipping the emoji font only in Linux artifacts | Would save 4.8MB on macOS and Windows. Left as a simplification rather than an oversight. |
| Per-state mask refinement for hit-testing | The union mask over-grabs slightly; per-state would make the grabbable area flicker. Not worth it. |
